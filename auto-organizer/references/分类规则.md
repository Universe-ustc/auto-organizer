# 分类规则

面向 Auto-Organizer 的判定细则。目标是让分类结果**可解释、可复核、可回滚**。

## 一、判定优先级

按顺序使用，前面的证据足够时不要继续往下：

1. **文件名关键词**：如“策划/方案/预算/发票/合同/简历/照片”。
2. **所在子目录与同批文件**：同一目录、同一命名批次通常属于同一主题。
3. **正文内容**：用 `extract_text.py` 抽取前 2000–4000 字，找标题、主题词、收件方。图片在本机有 Tesseract OCR 时含识别文本。
4. **时间与 EXIF**：拍摄时间、文档修改时间；用于把照片归入对应活动，而不是单独建“2023 年照片”类。
5. **内容哈希**：`scan.json` 的 `duplicate_groups`。SHA-256 相同才算重复。
6. **兜底**：以上都不成立 → `其他资料`，并在报告中写明原因。

注意：**目录名和文件名只是证据，不是结论**。例如“新建文件夹 (2)”没有信息量，应看内容。

## 二、类别设计

- 按**主题/环节**细分，不要按文件扩展名分。
- 主题不同就单独立类。策划、场地、经费、宣传、照片、总结是不同环节，即使某类只有 1–2 个文件也保留。
- **不要**用「活动筹备」把策划 + 场地 + 预算装进一个口袋。
- 不要为凑数量发明无意义的类；类数随真实主题走，不设 2–4 或 5–9 的硬指标。超过 9 类时再检查是否碎片化。
- 简历、合同、证件等个人材料单独成类（如 `个人材料`），不要因为只有 1 份就丢进 `其他资料`。
- 有真正杂项时，最后一类才是 `其他资料`；没有杂项就不要空留这一类。
- 有 SHA-256 相同的文件时，增加 `N 重复文件`：只把 `extras` 放进去，`keep` 仍进主题类。不删除文件。没有重复就不要建这一类。
- 编号从 **1 连续递增**，不跳号。
- 名称 2–8 个汉字，使用用户语境中的词，不要生造术语。
- 名称禁止包含 `\ / : * ? " < > |`，不要以空格或点结尾（Windows 限制）。
- 类别内按文件名或时间自然排序，不强制重命名文件。
- 文件会拍平到分类文件夹根下，不保留原来的子目录结构。

**好例子**：`1 活动策划`、`2 场地申请`、`3 经费预算`、`4 活动宣传`、`5 活动照片`、`6 活动总结`、`7 个人材料`、`8 其他资料`  
**坏例子**：`1 活动筹备`、`2 活动宣传`、`3 活动总结`（策划/场地/经费被装进一个口袋，过粗）  
**坏例子**：`1 文档`、`2 图片`、`3 其他`（按文件类型而非主题分类）

## 三、按文件类型的判定要点

### 文档类（docx / pdf / txt / md）

- 看标题、首段、落款、收件方。
- “策划案、方案、流程、主持词” → 活动策划类。
- “申请表、审批表、回执、场地” → 申请审批类。
- “预算、报销、发票、清单” → 经费类。
- “通知、推文、海报文案、宣传” → 宣传类。
- “总结、复盘、新闻稿、纪要” → 总结/新闻类。
- 合同、证件、简历等个人材料 → 单独归类，不要混入工作文档。

### 表格类（xlsx / csv）

- 看表头和 sheet 名：预算表、名单、排班表、物资清单。
- 名单类若服务于活动 → 归入该活动对应类别，不单建“表格”类。

### 图片（jpg / png / heic）

- 本机有 Tesseract OCR 时先看识别正文，再看 EXIF 拍摄时间和同批文件。
- 没有 Tesseract 则 notes 写「未 OCR：本机未安装或未找到 Tesseract OCR」，按文件名前缀（IMG_、DSC_、微信图片）和修改时间分组。不要只写「未 OCR」而不说缺什么。
- 不按“图片”单建一类，除非用户明确要求；照片通常服务于某个主题（活动照片、证件照、截图）。
- 截图、证件照、聊天图片属于不同用途，不要混在一起。

### 压缩包 / 安装包

- `.zip` 用 `extract_text.py` 列出内部文件名，按内容归类。
- 安装包（exe / msi / msix / appx）统一归入“软件安装包”或“其他资料”。
- 无法识别内容的压缩包不擅自解压，放 `其他资料` 并注明。

### 音视频

- 按文件名、拍摄时间、同批文件归类；不抽取内容。
- 大文件只移动、不复制、不转码。

### 旧格式与特殊文件

- `.doc/.xls/.ppt` 无法抽文本 → 按文件名/目录判断。
- 扫描版 PDF 无文本层 → 按文件名判断，报告中注明未 OCR 的原因（当前脚本不把 PDF 交给 Tesseract，Tesseract 只处理图片）。
- 隐藏/系统文件、符号链接、目录联接默认跳过，不进入分类。

## 四、plan.json 约定

```json
{
  "root": "绝对路径（可选，必须与命令行一致）",
  "categories": [
    {"folder": "1 活动策划", "description": "策划案、流程、方案"},
    {"folder": "3 其他资料", "description": "无法归入以上类别"}
  ],
  "moves": [
    {"path": "相对路径/文件名.docx", "target": "1 活动策划", "reason": "判定依据"}
  ],
  "unmatched": [
    {"path": "相对路径/未知文件.bin", "reason": "未识别原因"}
  ]
}
```

硬性要求：

- `moves[].path` 必须是相对路径，不能在根目录之外，不能指向 `.organize/`。
- 每个源文件只能出现一次；`target` 必须与某个 `categories[].folder` 完全一致。
- 每个扫描到的文件要么在 `moves`，要么在 `unmatched`，不要遗漏。
- `reason` 写具体证据（“文件名含策划”优于“看起来像策划”）。

## 五、边界情况

| 情况 | 处理 |
| --- | --- |
| 目标分类已存在同名文件 | 脚本自动追加 `(2)`、`(3)`，绝不覆盖 |
| 文件已在目标分类目录中 | 记为 skipped，不重复移动 |
| 文件被占用 | 记为 failed，继续处理其他文件，报告中列出 |
| 预先就空的文件夹 | 保持原样，扫描结果中提示 |
| 搬空的源目录 | apply 后删除；回滚按原路径重建 |
| 已在本 skill 的「1–2 位数字 + 空格 + 名称」目录中 | `already_categorized=true`，默认不二次移动。`2024 年报` 不算 |
| 根目录有多个同名文件 | 可分别进入不同分类；同分类内自动改名 |
| 隐藏文件 / 系统文件 | 默认跳过；用户明确要求时才加 `--include-hidden` |
| 符号链接 / 目录联接 | 跳过，避免循环和越界 |
| OneDrive 按需文件 | 读取正文可能触发下载；只按文件名判断，不强制读取 |
| 超长路径（>260 字符） | 脚本内部加 `\\?\` 前缀，无需手工处理 |
| SHA-256 相同的重复文件 | `keep` 进主题类，`extras` 进 `重复文件`；预览标明；不删除 |

## 六、安全与回滚

1. 先生成 plan，把完整文件树发给用户，用户确认后才 `--apply`。回滚同样先 dry-run；`latest` 只还原最近一次。
2. 只移动文件、不删除文件、不重命名源文件（重名除外）。搬空的源目录会删除，预先就空的目录保留。
3. 每次执行写 `.organize/journal-*.json` 与 `.organize/latest-journal.json`。
4. 回滚命令：

```bash
python scripts/organize.py rollback "<根目录>" --journal latest --apply
```

5. 回滚不覆盖原位置已有文件；冲突项会记录在 `.organize/rollback-*.json`。
6. 整理报告 `_整理报告.md` 会被下一次整理覆盖；执行记录 journal 不会自动删除。

## 七、输出前自检

- [ ] 按环节/主题细分；没有把策划、场地、预算装进同一个口袋。
- [ ] 编号连续；没有杂项就不要空留 `其他资料`。
- [ ] 每个扫描到的文件都有明确归属或进入 `unmatched`。
- [ ] 已分类文件默认留在 `unmatched`，除非用户要求重整理。
- [ ] 没有跨出根目录的路径。
- [ ] 没有把系统文件、隐藏文件、符号链接放进 `moves`。
- [ ] SHA-256 相同的文件：keep 在主题类，extras 在 `重复文件`，没有重复就不要建该类。
- [ ] 图片 notes 里有 OCR 结果，或写明未 OCR 的原因（缺 Tesseract / 格式不支持 / PDF 不走 OCR）。
- [ ] dry-run 输出与 plan 一致，文件数对得上。
- [ ] 向用户展示结构树和判定依据后再执行。
